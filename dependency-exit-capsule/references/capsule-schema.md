# Capsule Schema Reference

This document describes the structure, fields, and evidence tagging protocol
of the Dependency Exit Capsule output.

---

## How to Read the Capsule

The capsule is produced in two formats:

- **capsule.md** -- Human-readable Markdown report. Every statement or data
  point carries an inline evidence tag: `[OBSERVED]`, `[EXECUTED]`, or
  `[AI-SUGGESTED]`.
- **capsule.json** -- Machine-readable JSON. Every value is wrapped in an
  object containing `"value"` and `"tag"` fields.

Start with the Markdown version for review. Use the JSON version for
programmatic processing or integration with other tools.

---

## Evidence Tagging Protocol

### Why Tags Matter

The single most important quality of the capsule is that a reader can always
distinguish **verified facts** from **model-generated opinions**. This is a
core judging criterion and a best practice in any AI-assisted maintenance
workflow.

### Tag Definitions

| Tag | Meaning | Trustworthiness |
|---|---|---|
| `[OBSERVED]` | Data directly extracted from source code, manifest files, or public package registries. Produced by deterministic scanning and parsing. | **High** -- reproducible by re-running the scanner on the same repo. |
| `[EXECUTED]` | Results from actually running a command (test suite, linter, build tool). The raw output is preserved. | **High** -- reproducible on the same environment and commit. |
| `[AI-SUGGESTED]` | Generated by the open-weight AI model based on the observed evidence. May contain errors, hallucinations, or suboptimal advice. | **Medium to Low** -- must be reviewed by a human before acting on it. |

### Examples from the Pydantic Migration Scenario

**[OBSERVED] example:**
> pydantic is pinned at version 1.10.13 in requirements.txt (line 7),
> but pyproject.toml declares pydantic>=2 in its [project.dependencies]
> list. [OBSERVED]

**[EXECUTED] example:**
> pytest: 10 total, 9 passed, 1 failed, 0 errors. test_config.py::test_sites_file_loads
> failed with ImportError: cannot import name 'validator' from 'pydantic'. [EXECUTED]

**[AI-SUGGESTED] example:**
> Replace @validator("name") with @field_validator("name", mode="before")
> and update the import to from pydantic import BaseModel, field_validator.
> [AI-SUGGESTED]

## Capsule Sections

### 1. Header
- generated_at (ISO 8601 UTC timestamp)
- repository (URL or path)
- target_dependency (name and version)
- capsule_version (skill version)

### 2. Problem Identified -- `[OBSERVED]`
Plain-English description of the maintenance problem with file references.

### 3. Dependency Details -- `[OBSERVED]`
Package name, pinned version, required version, latest version, license,
last release date, repo URL, deprecation status.

### 4. Risk Indicators -- `[OBSERVED]`
Severity-rated indicators with evidence strings. See risk-rubric.md.

### 5. Usage Locations -- `[OBSERVED]`
File, line, snippet, type (import/call/config/decorator), API version.

### 6. AI-Generated Analysis -- `[AI-SUGGESTED]`
Model used, problem summary, recommended approach, migration steps,
proposed code changes (diffs), estimated effort, risks, suggested tests.

### 7. Executed Test Results -- `[EXECUTED]`
Framework, command, total/passed/failed/errors/skipped counts, raw output.

### 8. Additional Dependency Issues -- `[OBSERVED]`
Secondary findings: other problematic dependencies discovered during scan.

### 9. Compatibility & Maintenance Gaps -- Mixed tags
Gaps between what was found and what was addressed.

### 10. Unresolved Concerns & Limitations -- Mixed tags
Honest assessment of what the capsule does not cover.

### Evidence Summary
Aggregate counts: X observed, Y executed, Z AI-suggested.
